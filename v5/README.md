# Business Calendar System for Snowflake

## Overview

This solution provides a robust, conformed date dimension in Snowflake, following Kimball principles. It supports Gregorian, optional Fiscal and Retail calendars, and exposes dynamic, time-relative flags for BI and analytics. It also integrates Australian public holiday data from data.gov.au.

---

## Components

- **`DIM_DATE` Table**: Static calendar dimension with rich attributes.
- **`SP_GENERATE_DIM_DATE` Stored Procedure**: Generates and populates `DIM_DATE` based on parameters.
- **`VW_DIM_DATE_WITH_DYNAMIC_FLAGS` View**: Adds dynamic flags, offsets, and holiday info relative to query time.
- **`LOAD_AU_HOLIDAYS` Stored Procedure**: Loads Australian public holidays from data.gov.au into `PUBLIC_HOLIDAYS_AU` table.

## Setup Instructions

### 1. Create the Table and View

Run the following scripts in order:

- `dim_date.sql` — Defines the `DIM_DATE` table.
- `vw_dim_date_with_dynamic_flags.sql` — Defines the dynamic view.

### 2. Generate Calendar Data

Call the stored procedure to populate the calendar:

```sql
CALL SP_GENERATE_DIM_DATE(
    '2020-01-01',    -- Start date (inclusive)
    '2030-12-31',    -- End date (inclusive)
    TRUE,            -- Include Fiscal calendar attributes
    TRUE             -- Include Retail calendar attributes
);
```

- Set Fiscal/Retail flags to `FALSE` if not needed.
- The procedure is **idempotent**; it deletes overlapping dates before insert.

### 3. Load Australian Public Holidays

Run the holiday loader stored procedure (replace with your database and schema):

```sql
CALL LOAD_AU_HOLIDAYS('YOUR_DATABASE','YOUR_SCHEMA');
```

This fetches holidays from data.gov.au and populates the `PUBLIC_HOLIDAYS_AU` table.

## Usage Examples

### Query the Static Calendar Table

```sql
SELECT * FROM DIM_DATE WHERE YEAR_NUMBER = 2025;
```

### Query with Dynamic Flags and Holidays

```sql
SELECT *
FROM VW_DIM_DATE_WITH_DYNAMIC_FLAGS
WHERE IS_YTD = TRUE;
```

### Filter for Last 30 Days

```sql
SELECT *
FROM VW_DIM_DATE_WITH_DYNAMIC_FLAGS
WHERE IS_LAST_30_DAYS = TRUE;
```

### Filter for Public Holidays

```sql
SELECT *
FROM VW_DIM_DATE_WITH_DYNAMIC_FLAGS
WHERE IS_PUBLIC_HOLIDAY = TRUE;
```

## Notes

- Fiscal and Retail columns are nullable and populated conditionally.
- Dynamic flags are calculated at query time using `CURRENT_DATE()`.
- Public holiday info is joined dynamically from `PUBLIC_HOLIDAYS_AU`.
- Designed for extensibility — add columns or flags as needed.
- No daily update jobs required; refresh by rerunning the procedures if extending date range or updating holidays.

---

## Maintenance

- To extend the calendar, rerun `SP_GENERATE_DIM_DATE` with a new date range.
- To refresh holidays, rerun `LOAD_AU_HOLIDAYS`.
- To add new attributes, alter the table and update the stored procedure accordingly.
- To modify dynamic flags or holiday logic, edit the view definition.
